📊 1. Diagrama de Entidade-Relacionamento (ERD)

Duas tabelas para os três rádios. O que LoRa, Channel Sounding e celular têm em comum é o modelo inteiro: um dispositivo reporta uma observação sobre si mesmo ou sobre outro dispositivo. O rádio virou a coluna link, não um conjunto de tabelas separado.

    devices {
        text device_id PK "efuse MAC / FICR.DEVICEID / IMEI"
        text kind "tag | gateway"
        text link "lora | ble_cs | cellular"
        text label "Nome / apelido"
        text board_model "T-Beam / T-Echo / XIAO / T-SIM7000G"
        text firmware_version "Versão do firmware"
        text ingest_key_hash "SHA-256, só em quem escreve (oculto de anon)"
        timestamptz last_seen_at "Último contato"
        float8 last_lat "Última latitude válida [-90, 90]"
        float8 last_lng "Última longitude válida [-180, 180]"
        int4 last_battery_mv "Nível de bateria em mV"
        jsonb metadata "Dados extras"
        timestamptz created_at
        timestamptz updated_at
    }

    readings {
        bigserial id PK "ID sequencial"
        text device_id FK "devices(device_id) [CASCADE]"
        text reported_by FK "devices(device_id) [SET NULL] — null = auto-reporte"
        timestamptz recorded_at "Hora de inserção"
        timestamptz device_time "Timestamp do satélite"
        int4 seq "Contador de pacote"
        text status "fix|stale|acquiring|no_gps|ok|poor|failed"
        float8 lat "Latitude [-90, 90] — null quando desconhecida"
        float8 lng "Longitude [-180, 180] — null quando desconhecida"
        numeric hdop "Precisão horizontal"
        int4 sats "Satélites em uso"
        float8 distance_m "Channel Sounding: distância [0, 1000] m"
        int4 battery_mv "Tensão da bateria"
        int4 rssi "Potência de sinal (dBm)"
        numeric snr "Relação sinal-ruído"
        jsonb payload "JSON completo recebido"
    }

O que não foi unificado, de propósito: lat/lng e distance_m continuam em colunas separadas. Uma distância é um tipo de observação diferente de uma coordenada — e a posição absoluta de uma tag CS é derivada por uma view (origem + raio), nunca gravada como se fosse um fix.

    V_Latest --> Dashboard
    TBL_Readings --> Dashboard

A bridge não roteia mais. A RPC decide o que é a leitura a partir do payload: device_id ausente (ou igual ao dono da chave) ➔ auto-reporte, reported_by nulo; device_id apontando outro dispositivo ➔ encaminhada, reported_by = o gateway da chave.

📋 3. Dicionário de Dados

Campos, regras de negócio e restrições integradas no banco.

devices Tabela Base

Todo dispositivo rastreado e todo gateway, uma linha cada.

ColunaTipoRegra
device_idtext PKVem do silício: efuse MAC (12 hex), FICR.DEVICEID (16 hex) ou IMEI (15 díg.). Sem etapa de provisionamento.
kindtextCHECK tag | gateway. O que o dispositivo é.
linktextCHECK lora | ble_cs | cellular. Como ele fala. Uma tag encaminhada herda o link do gateway.
ingest_key_hashtext UNIQUESó em quem escreve (gateways e tags celulares). Nunca legível via API — GRANT por coluna, não por tabela.
last_lat / last_lngfloat8CHECK de faixa. Atualizados com coalesce: perder o fix não apaga a âncora do mapa.
last_battery_mvint4Aceita battery_mv ou bat_mv no payload.
metadatajsonbGuarda o primeiro payload visto e marcadores de atividade.

readings Tabela Base

Histórico append-only de toda observação, qualquer que seja o rádio.

ColunaTipoRegra
device_idtext FKdevices [ON DELETE CASCADE]. De quem é a observação.
reported_bytext FKdevices [ON DELETE SET NULL]. null = auto-reporte (tag celular, ou heartbeat do gateway).
statustext NOT NULLRelato do próprio dispositivo, nunca inferido aqui. Texto puro, não enum: um valor novo de firmware não pode derrubar leituras válidas.
lat / lngfloat8CHECK de faixa. null quando a posição é desconhecida — nunca um placeholder.
distance_mfloat8Channel Sounding. CHECK [0, 1000] m. Coluna própria: uma distância nunca pode ser lida como coordenada.
payloadjsonbO objeto inteiro recebido. Diagnósticos de firmware (uptime_ms, csq, rx_count…) chegam aqui sem mudança de schema.
CHECK readings_failed_has_no_measurement: se status = 'failed', então distance_m, lat e lng são obrigatoriamente nulos. É o banco garantindo que uma medição falha nunca carregue um número.

👁️ 4. View do Banco & Funções RPC

Camada de abstração exposta para o frontend e para os dispositivos.

View Analítica (com RLS)

  • VIEW latest_positions
    Usa DISTINCT ON (device_id) para trazer a última leitura de cada dispositivo — tags e gateways, LoRa, CS e celular, na mesma consulta. O mapa tira sua âncora daqui em vez de uma segunda query.
  • DERIVADO origin_lat, origin_lng, radius_m
    A posição derivada de uma tag ranged: o círculo em volta do gateway que a mediu. Calculado na view e nunca gravado — um palpite em coluna de posição seria indistinguível de um fix medido.
  • RLS security_invoker = on
    A view aplica o RLS do papel que consulta, não o de quem a criou.

Funções RPC (Security Definer)

  • RPC ingest(key, payload)
    O único caminho de escrita. Valida a chave (hash SHA-256), faz upsert do dispositivo e insere a leitura. Substituiu ingest_lora_packet, ingest_lora_gateway_status e ingest_cs_ranging — as três só diferiam em quais colunas liam. Concedida a anon e service_role.
  • RPC register_device(id, kind, link, board_model, label)
    Emite a chave de ingestão e a devolve uma única vez — só o hash fica guardado. Re-executar com o mesmo device_id rotaciona a chave. Concedida apenas a service_role: um papel capaz de emitir chaves tornaria a chave inútil.
